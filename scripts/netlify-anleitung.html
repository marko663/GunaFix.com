Solaris Industrial

Website online stellen

Netlify, kostenlos, ca. 15 Minuten. Funktioniert auf dem iPad — am Laptop ist es etwas bequemer. Diese Seite offen lassen und daneben arbeiten.

1

Standard-Branch auf GitHub setzen

1 Min.

Damit Netlify automatisch den richtigen Code nimmt.

  1. github.com/marko663/GunaFix.com öffnen und anmelden
  2. Oben rechts auf Settings (Zahnrad)
  3. Links im Menü auf Branches
  4. Bei Default branch auf das Symbol mit den zwei Pfeilen ⇄ tippen
  5. main auswählen → Update → I understand, update
Warum das wichtig ist Ohne diesen Schritt schlägt Netlify den alten Branch vor — das ist die alte Website, nicht die neue. Nichts geht verloren, alle Branches bleiben bestehen.
2

Bei Netlify anmelden

2 Min.
  1. app.netlify.com öffnen
  2. Sign up → GitHub
  3. GitHub fragt nach Erlaubnis → Authorize Netlify

Kein Zahlungsmittel nötig. Der kostenlose Tarif erlaubt auch geschäftliche Nutzung.

3

Projekt importieren

3 Min.
  1. Add new site → Import an existing project
  2. Deploy with GitHub
  3. Falls gefragt: Configure Netlify on GitHub → Konto wählen → Only select repositories → GunaFix.com anhaken → Save
  4. Zurück bei Netlify: in der Liste marko663/GunaFix.com antippen
Häufigster Fehler Wird das Repository nicht angezeigt, wurde bei Schritt 3 kein Zugriff erteilt. Erneut auf Configure Netlify on GitHub und das Repository anhaken.
4

Einstellungen prüfen

2 Min.

Der nächste Bildschirm zeigt die Build-Einstellungen. So muss es aussehen:

Branch to deploy .......... main
Base directory ............ (leer)
Build command ............. npm run build
Publish directory ......... .next

Diese Werte kommen automatisch aus der Datei netlify.toml im Projekt. Nichts ändern.

Steht bei Branch to deploy etwas anderes, jetzt auf main umstellen:

claude/gunafix-website-redesign-954ii5 ← falsch, alte Seite
main ← richtig
5

Eine Variable setzen — nicht überspringen

2 Min.
  1. Auf derselben Seite: Add environment variables bzw. Show advanced
  2. New variable
  3. Key und Value eintragen:

Key

SITE_NOINDEX

Value

true
Warum zwingend Die Seite enthält noch Platzhalter — erfundene Zahlen und Projekte. Diese Variable sperrt Google komplett aus. Ohne sie könnten falsche Angaben über ein echtes Unternehmen in der Suche landen. Am Tag des echten Livegangs wird sie wieder entfernt.

Die Variablen für Sanity und den E-Mail-Versand kommen später dazu. Die Website läuft auch ohne sie.

6

Veröffentlichen

4 Min.
  1. Deploy site antippen
  2. Warten. Der Bildschirm zeigt Building…, dann Published
  3. Oben erscheint eine Adresse wie random-name-1a2b3c.netlify.app

Adresse verschönern:

  1. Site configuration → Change site name
  2. Eintragen: solaris-industrial-demo
  3. → solaris-industrial-demo.netlify.app
7

Prüfen, bevor der Kunde es sieht

3 Min.

Die neue Adresse öffnen und der Reihe nach abhaken:

Die Startseite erscheint auf Deutsch

Oben rechts EN antippen → alles wird englisch, gleiche Seite

Menü durchklicken: Carports, GroundForce, Projekte, Wissensdatenbank, Kontakt

Ein Carport-Modell öffnen — die Adresse endet auf /de/carports/mega

Am Ende der Adresse /robots.txt anhängen → dort muss Disallow: / stehen

Am Ende der Adresse /studio anhängen → Hinweisseite „Noch nicht verbunden"

Alles grün? Dann kann die Adresse an den Kunden gehen. Der Punkt Disallow: / ist der wichtigste — er beweist, dass Google die Demo nicht indexiert.
?

Wenn etwas nicht klappt

Das Repository erscheint nicht in der Liste

Netlify hat keinen Zugriff. Auf Configure Netlify on GitHub tippen, das Konto wählen, Only select repositories → GunaFix.com anhaken → speichern.

„Build failed" — der Aufbau bricht ab

Auf Deploys → den fehlgeschlagenen Eintrag → das Protokoll öffnen. Die letzten 20 Zeilen kopieren und mir schicken. Ein sauberer Aufbau wurde hier bereits geprüft, deshalb ist fast immer der falsche Branch oder eine fehlende Variable die Ursache.

Die Seite zeigt 404

Die Adresse ohne Zusatz aufrufen, also nur …netlify.app. Die Startseite leitet selbstständig auf /de um.

Der Sprachumschalter fehlt

Auf dem Handy steht er in der oberen schmalen Leiste ganz rechts, neben Telefonnummer und E-Mail.

Bei robots.txt steht nicht „Disallow: /"

Die Variable aus Schritt 5 fehlt oder ist falsch geschrieben. Unter Site configuration → Environment variables prüfen: exakt SITE_NOINDEX mit dem Wert true. Danach unter Deploys → Trigger deploy → Clear cache and deploy site.

Sanity-Projekt anlegen und verbinden (siehe CMS-SETUP.md)

Klären, wessen Firma das ist — erfundene Angaben entfernen

Echte Texte, Fotos und Firmendaten einpflegen

Eigene Domain verbinden

Variable SITE_NOINDEX entfernen
