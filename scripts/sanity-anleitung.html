Solaris Industrial

Redaktionszugang einrichten

Damit der Kunde Texte und Bilder selbst ändern kann. Kostenlos, ca. 20 Minuten, komplett im Browser — auch auf dem iPad. Es wird kein Terminal benötigt.

1

Sanity-Projekt anlegen

4 Min.
  1. sanity.io/manage öffnen
  2. Anmelden mit Google oder GitHub
  3. Create new project
  4. Name: Solaris Industrial
  5. Dataset: production, Sichtbarkeit Public
  6. Create project
Project ID notieren Auf der Projektseite steht oben eine Project ID — acht Zeichen, etwa a1b2c3d4. Diese wird gleich dreimal gebraucht.

„Public" bezieht sich nur auf das Lesen der Texte — die Website muss sie ja anzeigen können. Bearbeiten darf weiterhin nur, wer eingeladen wurde.

2

Zugriffsschlüssel erzeugen

2 Min.
  1. Im Projekt auf API
  2. Abschnitt Tokens → Add API token
  3. Name: Seed
  4. Berechtigung: Editor
  5. Save
Der Schlüssel wird nur ein einziges Mal angezeigt Sofort kopieren und sicher ablegen. Er beginnt mit sk… und erlaubt das Ändern aller Inhalte. Niemals in einen Chat, eine E-Mail oder ins Projekt schreiben. Falls verloren: löschen und einen neuen erzeugen.
3

Website freischalten (CORS)

2 Min.

Ohne diesen Schritt bleibt /studio weiß.

  1. Weiterhin unter API → Abschnitt CORS origins
  2. Add CORS origin
  3. Die Adresse der Website eintragen, ohne Schrägstrich am Ende
  4. Allow credentials aktivieren ✅
  5. Save

Beispiel

https://IHRE-ADRESSE.netlify.app
4

Zwei Geheimnisse bei GitHub hinterlegen

3 Min.
  1. github.com/marko663/GunaFix.com → Settings
  2. Links: Secrets and variables → Actions
  3. New repository secret — zweimal, einmal je Eintrag:

Name 1

SANITY_PROJECT_ID

Wert 1

die Project ID aus Schritt 1

Name 2

SANITY_WRITE_TOKEN

Wert 2

der sk… Schlüssel aus Schritt 2

GitHub verschlüsselt beide Werte. Sie sind danach nicht mehr lesbar — auch nicht für Sie. Das ist so gewollt.

5

Inhalte ins CMS laden

2 Min.

Damit der Kunde nicht vor leeren Feldern sitzt, werden die vorhandenen Texte einmalig übertragen — auf den Servern von GitHub, ohne eigenen Rechner.

  1. Im Repository oben auf Actions
  2. Links auf Inhalte ins CMS laden
  3. Rechts auf Run workflow → Branch main → Run workflow
  4. Ca. eine Minute warten, bis ein grüner Haken erscheint
Ergebnis 19 Dokumente: Allgemein, GroundForce, 5 Baureihen, 6 Projekte, 6 Fachbeiträge — alle mit deutschem und englischem Text.

Der Ablauf lässt sich beliebig wiederholen. Er ersetzt Texte und rührt hochgeladene Fotos nicht an.

6

Website mit dem CMS verbinden

3 Min.
  1. Bei Netlify: Site configuration → Environment variables
  2. Add a variable — zwei Einträge:

Variable 1

NEXT_PUBLIC_SANITY_PROJECT_ID = die Project ID

Variable 2

NEXT_PUBLIC_SANITY_DATASET = production
  1. Deploys → Trigger deploy → Clear cache and deploy site
  2. Zwei bis vier Minuten warten
Der Schlüssel aus Schritt 2 gehört hier nicht hinein Nur die Project ID und das Dataset. Der sk… Schlüssel bleibt ausschließlich bei GitHub.
7

Prüfen

2 Min.

/studio aufrufen — jetzt erscheint eine Anmeldung statt des Hinweistextes

Anmelden mit demselben Konto wie bei Sanity

Links stehen: Allgemein, GroundForce, Carport-Baureihen, Projekte, Fachbeiträge

Eine Baureihe öffnen — Felder sind gefüllt, je Feld Deutsch und English

Eine Überschrift ändern → Publish → nach ca. einer Minute auf der Website sichtbar

Das ist der Moment für den Verkauf Genau diesen letzten Punkt dem Kunden zeigen: Text ändern, veröffentlichen, Website neu laden. Das rechtfertigt den Posten „Redaktionszugang".
8

Kunden einladen

2 Min.
  1. sanity.io/manage → Projekt → Members
  2. Invite members → E-Mail des Kunden
  3. Rolle: Editor (nicht Administrator)
  4. Send invitation

Editor darf Inhalte ändern, aber keine Zugänge verwalten und das Projekt nicht löschen. Die genaue Anzahl freier Plätze steht im Tarifüberblick bei Sanity.

?

Wenn etwas nicht klappt

/studio bleibt weiß

CORS fehlt. Schritt 3 wiederholen und prüfen, dass die Adresse exakt stimmt — ohne Schrägstrich am Ende — und Allow credentials aktiviert ist. Danach die Seite neu laden.

/studio zeigt weiterhin „Noch nicht verbunden"

Die Variablen aus Schritt 6 fehlen oder der Neuaufbau lief noch nicht. Unter Deploys → Trigger deploy → Clear cache and deploy site. Ein einfacher Neustart genügt nicht, weil die Werte beim Bauen eingebettet werden.

Der Ablauf bei GitHub schlägt fehl

Das Protokoll nennt die Ursache. „SANITY_PROJECT_ID fehlt" bedeutet, dass Schritt 4 unvollständig ist. „Unauthorized" bedeutet, dass der Schlüssel nicht die Berechtigung Editor hat — dann in Sanity einen neuen erzeugen und das Geheimnis bei GitHub aktualisieren.

Im Studio sind alle Felder leer

Schritt 5 lief nicht oder lief gegen ein anderes Projekt. Prüfen, dass SANITY_PROJECT_ID bei GitHub und NEXT_PUBLIC_SANITY_PROJECT_ID bei Netlify dieselbe ID enthalten.

Änderungen erscheinen nicht auf der Website

Im Studio muss Publish gedrückt werden — ein Entwurf allein genügt nicht. Danach bis zu einer Minute warten; die Seiten werden 60 Sekunden zwischengespeichert.

Danach ist offen

Klären, wessen Firma das ist — erfundene Angaben entfernen

Echte Texte, Fotos und Firmendaten einpflegen

Impressum und Datenschutz mit echten Daten füllen

Eigene Domain verbinden

SITE_NOINDEX entfernen und neu veröffentlichen
